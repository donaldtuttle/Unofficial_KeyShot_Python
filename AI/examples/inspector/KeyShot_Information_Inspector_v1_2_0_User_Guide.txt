# KeyShot Information Inspector v1.2.0 — Complete User Guide

**Unofficial community utility · KeyShot 2026.x · Python script · GUI only**  
**First public-release guide:** 2026-10-23 · **Script covered:** `KeyShot_Inspector_1_2.py` (version 1.2.0)

> **Purpose:** An inspection and diagnostic utility for KeyShot 2026.x with **74 selectable report operations across 12 categories**. Generate console output, a UTF-8 `.txt` report, or both. Ordinary reports are scene-read-only. Optional all-saved-item inventories temporarily change the active camera, environment, or image style, and attempt to restore it. This is the complete guide for the first community release, **v1.2.0**, not a change log or an addendum. The script has passed offline tests but has not been certified crash-free across live KeyShot scenes.

## Background and motivation

When I first started scripting in KeyShot, I didn't realize just how often I'd need the `get` commands—or how useful they would become. Initially, they seemed like simple ways to retrieve information. As my scripts became more complex, I found myself using them constantly to understand what KeyShot was actually storing in the scene and material graphs.

**Material scripting made this especially clear.** The Python API documents how to access material graphs and shader parameters, but it doesn't provide a comprehensive list of the exact internal parameter names and values for every shader type. A parameter's name in the Material Graph interface isn't necessarily the name a Python script must use. To write dependable scripts, I learned to query the live material graph: retrieve its shader nodes, identify their types, and enumerate their actual parameter names, types, values, and connections. That revealed details I couldn't reliably determine from the documentation alone.

Over time, my smaller inspection scripts became a collection of tools I kept returning to. The Information Inspector grew out of that experience: it puts many of those `get` commands in one place, lets you select only the information you need, and makes it easier to document a scene or investigate a scripting problem. **If you're learning KeyShot Python, inspecting the live scene is often the first step toward writing a script that works reliably.**

## 1. What is it for?

KeyShot exposes scene, material, camera, rendering, and resource information through its Python `lux` API. The Inspector bundles many of these read operations into one GUI. Instead of running a different Python script for every question, select the relevant report and export the results.

Common uses: document a scene for handoff; locate unexpected materials or geometry-node connections; inspect node naming and hierarchy; compare render/lighting settings; identify referenced external files; and prepare a focused diagnostic report for a KeyShot forum discussion.

**Standard reports do not call scene setters.** They do not advance the timeline, rename objects, modify materials, reconnect shaders, delete nodes, or render images. **Exception:** when the separately named *Inspect ALL cameras/environments/styles via switching/restoring* option is enabled, the inspector uses `setCamera()`, `setActiveEnvironment()`, and `setActiveImageStyle()` to examine saved items and tries to restore the original active selection. **Use that option on a saved copy of your scene.** Restoring a selection is not a guarantee that every transient side effect is undone, and a native crash prevents Python cleanup from running. The script can write a TXT report, crash trace, and optional `.metadata` / `.xmp` files. Native API calls can still be slow or unstable.

## 2. Install and launch

1. Save `KeyShot_Inspector_1_2.py` to a convenient folder (for example, KeyShot's Scripts resource directory).
2. Open a KeyShot scene; access KeyShot's **Scripts** interface and run the `.py` file.
3. In the first dialog, choose the category/report settings and destination. In **Individual Gets** mode, choose **one** category from the dropdown; a second dialog will show only that category's operations.
4. Choose **Save TXT only** for large diagnostic reports; select an existing output folder and a filename.
5. Run. Inspect the resulting text report and—if troubleshooting—the separate trace file.

If you cancel the first dialog, no new trace starts. If you cancel the second dialog, the trace records the cancellation. KeyShot GUI dialogs cannot run in headless mode.

## 3. How the two selection modes work

**Category mode (default):** The 12 category checkboxes control which groups run. Within each selected group, the script runs only operations marked *Default ON* in the reference below, not every operation in that group.

**Individual Gets mode:** Check *Individual Gets mode: ONE category per run*, choose a category in the adjacent dropdown, and continue. The next dialog lists every report option for **that one category**. Tick the exact operations you want. The first dialog's category checkboxes do not determine which individual reports run in this mode.

The script deliberately limits Individual Gets to one category per run to avoid opening many consecutive native KeyShot checkbox dialogs.

## 4. Main GUI settings

| Setting | What it controls |
|---|---|
| **Report destination** | `Print to console`, `Save TXT only`, or `Print and save TXT`. |
| **TXT output directory** | Existing directory for the TXT report; also the preferred directory for the trace. |
| **TXT filename** | A base filename, sanitized and given `.txt`. Existing files are not silently overwritten; a dated name is used instead. |
| **Individual Gets mode** | Choose specific report operations within one category. |
| **Category for Individual Gets mode** | Category dropdown; used only when Individual Gets is checked. |
| **Max scene nodes to inspect** | Default `700`; limits `walk_scene()`-based hierarchy/transform/metadata/animation reports. Truncated results are possible on large scenes. |
| **Max nodes for per-node animation scan** | **Known v1.2.0 limitation:** this field currently is not used by any reporter. Adjust `Max scene nodes to inspect` instead. |
| **Max output per GET (KB)** | Default `18`; truncates each operation's *formatted text* (after the getter executes). It does not necessarily limit native API work. |
| **Allow slow scans / library loading** | Default OFF. Required for Resource Models disk scan, all-library inventories, `dumpTree()` output, and library CMF metadata. |
| **Allow advanced animation scene-tree scanning** | Default OFF. Required for animation node hierarchy and current-frame animated-parent bounds. Not required for basic animation duration/time/frame. |
| **Inspect ALL cameras/environments/styles via switching/restoring** | Default OFF. Temporarily activates every saved camera, environment, or image style when its all-saved report is selected, reads active-item properties, and attempts to restore the original active selection. **Changes active state during inspection; use a saved scene copy.** |
| **Exhaustive output: no scene/material/section caps** | Default OFF. Removes most inspection and formatted-output limits. May take significant time, memory, and disk space. Resource Models disk scan remains separately bounded. |
| **Optional library material for CMF metadata** | Exact name of **one material in the KeyShot material library**, used only when the CMF operation is selected and slow scans are enabled. Default placeholder is not an actual material selection. |

**Standard internal limits:** material graph reporters inspect up to **40 scene materials** and **120 shader nodes per material**; `getObjectMaterial()` uses up to **100 object IDs**. The **Exhaustive output** checkbox lifts those scene/material/shader/section and object-ID caps (and can generate huge reports). It does **not** remove the Resource Models filesystem limits of **150 directories / 300 matches**, unblock library scans, or unblock the two native animation-object getters. Output caps only constrain data formatting after some native calls have completed.

## 5. Suggested starting presets

| Goal | Choose |
|---|---|
| **Basic scene handoff** | Scene summary; saved camera names and active-camera details; materials list; studio detail; external files. |
| **Unexpected material appearance** | Material names; graph outline; shader parameters/input sources; detailed edges; geometry nodes; labels. Start with one group. |
| **CAD hierarchy / selection issue** | Scene hierarchy; names/types; full paths; parent relationships; hidden/locked/selected lists. |
| **Render reproducibility** | Render options; render engine; lighting preset; active environment; image-style settings; studio details. |
| **Compare ALL saved cameras** | In Individual Gets, select Cameras → ALL saved cameras; enable temporary switching in the main dialog. Save the scene first. |
| **Audit ALL environment setups** | Select Environments → ALL saved environments; enable temporary switching. Review brightness, HDRI, ground, backplate, and rotation separately for each. |
| **Compare saved image styles** | Select Image styles → ALL saved image styles; enable temporary switching. Basic styles skip Photographic-only color and curve getters. |
| **Export native metadata** | Select Scene → Export native .metadata and .xmp files; provide a writable existing output folder. Two files are created, separate from the TXT report. |
| **Animation diagnosis** | First run **getAnimationInfo() / Time / Frame** only. Later, optionally enable animation-tree scanning. Avoid the two disabled native animation getters. |
| **Missing external textures** | External file references; resource folder paths. This does not scan the entire drive. |
| **Resource inventory** | Select Library Inventories or Resource Models only with *Allow slow scans* enabled and expect possible library-loading delays. |

## 6. Reference: all 74 selectable reports

All 74 options below use the labels and organization from the actual v1.2.0 registry. **Default ON** means the option runs when its category is checked in category mode; **Individual only** means the user must select it explicitly in Individual Gets mode. Any selected operation remains subject to its safety gates.

### Scene / configuration / metadata (8 options)

**getSceneInfo() - Scene summary** — **Default ON**. Scene name, file path, units and scale, counts of objects/triangles/NURBS/curves, scene and render dimensions. **Why use it:** Quick scene audit, geometry complexity checks, scene handoff.

**getActiveConfiguration() - Configuration** — **Default ON**. Active configurator state returned as a dictionary; can be empty if no active configuration. **Why use it:** Document the currently selected variant.

**getSceneColors() / getSceneColor() - Scene colors** — *Individual only*. Currently used scene colors and multi-colors with available color/sub-color details; no RGB conversion. **Why use it:** Inventory reusable scene color assets and variants.

**getSceneColor() - Individual color details** — *Individual only*. Looks up each named scene color with getSceneColor() and reports its available color or sub-color information. **Why use it:** Investigate one-to-many color setup and color asset references.

**getColorways() - Colorways** — *Individual only*. Colorway names plus their associated color choices via getColorway(). **Why use it:** Document product colorway variants.

**getMetaData() - Simple metadata** — *Individual only*. Scene metadata in the KeyShot SIMPLE format. **Why use it:** Document metadata shipped with the scene in a concise form.

**getMetaData() - XMP metadata (large)** — *Individual only*. Scene metadata in XMP/XML form; can be very long. **Why use it:** Technical interchange, auditing embedded metadata.

**Export native .metadata and .xmp files (user folder)** — *Individual only*. Retrieves both native `getMetaData(format=META_DATA_SIMPLE)` and `getMetaData(format=META_DATA_XMP)` payloads and writes separate, non-overwriting `.metadata` and `.xmp` files to the folder chosen in the main dialog. **Why use it:** Preserve the actual full metadata payloads for archival, analysis, or comparison without scraping a truncated TXT section. These are **current-scene metadata exports**, not one export per saved camera or environment.


### Scene tree / node details (11 options)

**getSceneTree() - Hierarchy** — **Default ON**. Indented hierarchy from getSceneTree(): names and node types. **Why use it:** Understand CAD imports, group organization and hierarchy.

**SceneNode getters - IDs, states and paths** — *Individual only*. Scene-node identifiers, materials, visibility, locking, selection, paths, and metadata where available. **Why use it:** Audit node setup and find problem parts; IDs are session-specific.

**SceneNode.getSelected() - Selected nodes** — *Individual only*. Detailed information for nodes selected in the KeyShot interface. **Why use it:** Inspect only the parts currently of interest.

**Node transforms / center / bounds** — *Individual only*. Local and world transform matrices, world centers and world-space bounding boxes for visited nodes. **Why use it:** Check geometry positioning and scene scale without moving anything.

**dumpTree() - Full JSON tree (large)** — *Individual only*. KeyShot's dumpTree() JSON representation of the scene hierarchy; output is size-limited. **Why use it:** Machine-oriented diagnostic comparison; may be large.

**SceneNode.getName() - Names only** — *Individual only*. A flat list of scene-node names. **Why use it:** Copy naming inventory into a search or auditing workflow.

**getName() / getKind() - Names and types** — *Individual only*. Every visited node's name and node kind (group, model, object, etc.). **Why use it:** Find type mismatches after CAD import.

**getPath() - Node paths** — *Individual only*. Full root-to-node path expressed as node names. **Why use it:** Disambiguate repeated part names and identify nesting.

**getHidden / getLocked / getDeleted / getSelected** — *Individual only*. Recursive lists of hidden, locked, deleted and selected nodes. **Why use it:** Understand why objects cannot be seen or selected.

**SceneNode.getMetadata() - Per-node metadata** — *Individual only*. Metadata dictionaries attached to scene-tree nodes; prints nonempty entries. **Why use it:** Audit imported CAD/component metadata.

**SceneNode.getParent() - Parent relationships** — *Individual only*. Node-to-parent relationship list. **Why use it:** Trace model organization and check nested CAD assemblies.


### Model sets / objects / layers (6 options)

**getModelSets() - Active model sets** — **Default ON**. Names of currently active model sets. **Why use it:** Verify the visible model-set state.

**Scene tree - All model sets** — **Default ON**. Hierarchy of each model set with its descendants and full node paths. **Why use it:** Prepare model-set-specific scene documentation.

**getObjects() - Object IDs** — *Individual only*. Numeric IDs for scene objects (IDs are temporary/session-specific). **Why use it:** API troubleshooting and correlating object assignments in one session.

**getMaterialMapping() - Object materials** — *Individual only*. Object ID to material-name mapping. **Why use it:** Determine where materials are assigned.

**getObjectMaterial() - Object material assignments** — *Individual only*. Runs getObjectMaterial() for up to 100 object IDs in standard mode (all IDs in exhaustive mode) and prints the material mapping too. **Why use it:** Compare object-specific material assignments with the scene mapping.

**getRenderLayers() - Render layers** — **Default ON**. Names of render layers present in the scene. **Why use it:** Audit render-pass organization.


### Materials / graphs / parameters (14 options)

**getSceneMaterials() - Material names** — **Default ON**. Names of materials currently used by the scene. **Why use it:** Material inventory before cleanup or handoff.

**getMaterialGraph() - Node IDs and types** — **Default ON**. Names, node IDs, node types and sub-material roots for up to 40 materials. **Why use it:** See material graph complexity and shader presence.

**ShaderNode.getParameters() - All values** — *Individual only*. Named shader parameters, display names, types, and readable values; pure parameters are flagged. **Why use it:** Troubleshoot material appearance or document exact values.

**ShaderNode edges - Connections** — *Individual only*. Shader output connections, source/target names, edge IDs and enabled flags. **Why use it:** Detect disconnected textures and unexpected material wiring.

**getMultiMaterial() - Sub-materials** — **Default ON**. Multi-material containers and their active/available sub-materials. **Why use it:** Audit material variations.

**Shader parameters / input sources (large)** — *Individual only*. For each shader parameter: type, pure state, literal if readable and any feeding input edge; color getter when applicable. **Why use it:** Diagnose texture-driven or animation-driven material behavior; potentially very large.

**Graph edges, target sockets, enabled states** — *Individual only*. Enumerates graph connections, attempts to resolve the target socket and shows enabled status. **Why use it:** Technical debugging of material graph wiring.

**MaterialGraph lookup getters (IDs / type)** — *Individual only*. Exercises selected root, node-by-ID, node-by-type, parameter and edge lookup methods using actual graph data. **Why use it:** Verify KeyShot API relationships with valid references, not random IDs.

**Shader types inventory including OpenPBR** — *Individual only*. Counts shader node types (including detected OpenPBR nodes) and lists materials using each type. **Why use it:** Find legacy materials or plan material standardization.

**Geometry-node connections (Fuzz/Flakes/Bubbles/Displace)** — *Individual only*. Geometry node inventory (Fuzz, Flakes, Bubbles, Displace), input/output counts and connection status. **Why use it:** Identify potentially inactive geometry effects without changing connections.

**Potentially disconnected/orphan shader nodes** — *Individual only*. Reports shader branches not reachable from material roots, excluding protected roots/constant colors/animation shaders. **Why use it:** Identify potential graph clutter for manual review; not a deletion recommendation.

**Material labels and root connections** — *Individual only*. Candidate label shader edges associated with material roots, based on shader-label socket types. **Why use it:** Audit label assets and label connection issues.

**Material graph Color/Curve Fade animation nodes** — *Individual only*. Color Fade / Curve Fade shader nodes and their documented readable parameters. **Why use it:** Find material graph animation independently of scene-tree animation.

**MaterialMetadata.getFieldNames/readField (library)** — *Individual only*. Reads text metadata fields of ONE explicitly named library material via findMaterialMetadata; image fields cannot be read. **Why use it:** CMF cataloging for product/material libraries; requires slow-library opt-in.


### Cameras / all saved camera settings (5 options)

**getCameras() - Saved camera names** — **Default ON**. Saved camera names only. **Why use it:** Audit view variants and presentation shot lists.

**getCamera() / Lens / Spherical** — **Default ON**. Name, lens dictionary and spherical angles of the ACTIVE camera. **Why use it:** Document the viewport camera setup.

**getCameraPosition(), direction, look-at** — **Default ON**. Active camera position, direction, look-at, pivot, up vector and distance. **Why use it:** Rebuild framing or check camera geometry.

**getCameraFieldOfView(), focal length** — **Default ON**. Lens information, field of view and focal length of the ACTIVE camera. **Why use it:** Match perspective and photographic framing.

**ALL saved cameras - all documented settings (switch/restore)** — **Default ON, but gated**. Uses `getCameras()` and temporarily activates each camera (only if the separate main-dialog switch permission is checked), then reads lens settings, FOV, focal length, world position, direction, up, look-at, pivot, distance, spherical angles and unsaved status. Verifies and restores the original active camera after each item. Refuses the all-camera scan if `isCameraUnsaved()` reports unsaved camera changes or raises. **Why use it:** Produce a complete per-camera technical audit, compare saved views, or reconstruct shot setups. **Safety:** do not run on unsaved work; a native process crash can interrupt restoration.


### Environments / all saved settings (3 options)

**getEnvironments() - Saved names** — **Default ON**. Saved environment names. **Why use it:** Audit lighting-environment choices.

**getActiveEnvironment() - Full settings** — **Default ON**. Active environment image, brightness, rotation, backplate, background and ground properties. **Why use it:** Reproduce lighting and ground appearance.

**ALL saved environments - all Env getters (switch/restore)** — **Default ON, but gated**. With temporary switching explicitly enabled, walks all saved environment names and reports the 14 documented `Env.get*` properties: name, background color, backplate, brightness, flatten ground, ground reflections, ground shadows, ground-shadow color, ground size, height, lighting environment image, occlusion ground shadows, rotation and size. **Why use it:** Compare lighting and background setups across every environment, not just the active one. The script attempts restoration after each environment.


### Image styles (3 options)

**getImageStyles() - Saved styles** — **Default ON**. Saved image-style names. **Why use it:** Inventory postprocessing profiles.

**getActiveImageStyle() - Active settings** — **Default ON**. Active image style type and bloom, aberration, denoise, vignette; Color/Curve only for Photographic styles. **Why use it:** Document image look while avoiding the Basic-style error.

**ALL saved image styles - full settings (switch/restore)** — *Individual only; gated*. With temporary switching enabled, selects each saved image style, reads kind, bloom, chromatic aberration, denoise, vignette, and (for Photographic styles only) Color and Curve; then tries to restore the original image style. **Why use it:** Compare saved appearance/postprocessing presets without manually cycling through them.


### Studios (3 options)

**getStudios() - Saved studios** — **Default ON**. Saved studio names. **Why use it:** Audit presentation states.

**getActiveStudio()** — **Default ON**. Currently active studio name. **Why use it:** Record the scene's active presentation state.

**getStudio() - All studio settings** — **Default ON**. Each studio's camera, environment, image style, model sets and multi-material state. **Why use it:** Compare alternate render setups without activating them.


### Render / lighting settings (6 options)

**getRenderOptions().getDict()** — **Default ON**. Current rendering options as the documented settings dictionary. **Why use it:** Reproduce output configuration and render quality.

**getRenderOptions(defaults=True).getDict()** — *Individual only*. KeyShot's internal default render options for comparison. **Why use it:** Find settings changed from defaults.

**getRenderEngine()** — **Default ON**. Identifier of the active render engine. **Why use it:** Diagnose CPU/GPU or product/interior engine selection.

**getLightingPreset()** — **Default ON**. Current lighting preset name. **Why use it:** Reproduce lighting choices.

**getLightingPresets()** — **Default ON**. Names of available lighting presets. **Why use it:** See which presets the installation exposes.

**getKeepAspectRatio() / getLockResolution()** — *Individual only*. Aspect-ratio and resolution-lock flags. **Why use it:** Explain resolution changes or fixed aspect behavior.


### Animation (5 options)

**getAnimationInfo() / Time / Frame** — **Default ON**. Duration and total frame count, active timeline time and current frame. Sub-calls are traced separately. **Why use it:** Basic animation diagnosis without advancing the timeline.

**getAnimations() - DISABLED native call (status only)** — *Individual only*. Reports whether native getAnimations() exists; DOES NOT call it due to prior crash reports. **Why use it:** API awareness without risking the process.

**getNodeAnimations(node) - DISABLED native call (status only)** — *Individual only*. Reports whether native getNodeAnimations(node) exists; DOES NOT call it. **Why use it:** API awareness without risking native iteration.

**Scene animation-node hierarchy (advanced opt-in)** — *Individual only*. Scene-tree nodes marked as animations, their IDs and parent nodes; requires advanced opt-in. **Why use it:** Find which objects own animation nodes; may be slow in large scenes.

**Animated parent world bounds (advanced opt-in)** — *Individual only*. At CURRENT frame only, returns animated parents' world-space bounding boxes, centers and transforms; advanced opt-in. **Why use it:** Inspect animated geometry pose without moving timeline.


### Resources / libraries / imports (6 options)

**getKeyShotFolder() - All resource paths** — **Default ON**. Paths to KeyShot's resource folders and Scripts/Scenes/Models/Textures locations. **Why use it:** Locate assets and customize shared resource installation.

**getExternalFiles()** — **Default ON**. External asset file paths referenced by the active scene. **Why use it:** Identify missing textures and package dependencies.

**Resource Models - BIP/KSP files (disk scan)** — *Individual only*. Bounded on-disk search for .bip/.ksp files inside the resource Models folder; slow opt-in. **Why use it:** Locate saved model assets; scans up to 150 folders / 300 matching files.

**getMaterialTemplates()** — *Individual only*. Names of available material templates. **Why use it:** Verify material-template availability for imports.

**getImportOptions()** — *Individual only*. Current import-options dictionary. **Why use it:** Explain CAD import tessellation or orientation behavior.

**getLibrary...() - All library inventories (slow)** — *Individual only*. Queries KeyShot's loaded material, texture, color, environment and backplate libraries; slow opt-in. **Why use it:** Resource library inventory; KeyShot warns first-time loading may block.


### KeyShot version / system (4 options)

**getKeyShotVersion() / getOS()** — **Default ON**. KeyShot display version, detailed engine version and operating system. **Why use it:** Record environment for reproducible bug reports.

**getSystemInfo()** — **Default ON**. System details as exposed by getSystemInfo() (hardware, display, process, locale and possibly license information). **Why use it:** Troubleshoot performance and compatibility; redact before posting publicly.

**hasContents()/is*() - Scene status flags** — *Individual only*. Scene contents/changed state, unsaved camera, headless/performance/paused/undo flags. **Why use it:** Fast read-only health and status check.

**2026 API getter availability audit** — *Individual only*. Checks whether each of 59 documented non-dialog get* functions exists in the runtime; DOES NOT execute them. **Why use it:** Check API availability after a KeyShot update, not runtime safety.


## 7. Inspecting ALL saved cameras, environments, and image styles

KeyShot's detailed getters generally describe the **active** item. The list getters (`getCameras`, `getEnvironments`, and `getImageStyles`) give the names of all saved items, but not every saved item's full properties in one read-only request. For a complete inspection, the program can temporarily select each saved item, query its properties, and attempt to return to the original active item.

**How to run a complete inventory:** Save a copy of the scene and ensure its current camera has no unsaved edits. In the main dialog, choose **Save TXT only**; enable **Inspect ALL cameras/environments/styles via switching/restoring**. In Individual Gets mode choose one category at a time and select its **ALL saved ... (switch/restore)** report. After running, check the `Final active ...` line and the trace's `RESTORE` checkpoints; verify the active item visually in KeyShot.

**Why this is opt-in:** `setCamera`, `setActiveEnvironment`, and `setActiveImageStyle` are state-changing API functions. Although the inspector restores the previous active *selection* after each attempt and aborts if restoration fails, these calls can cause live rendering or scene-change side effects. Restoration cannot be guaranteed if KeyShot crashes natively. This is not the same as a purely read-only operation.

**What will be recorded:**

| Inventory | Property coverage | Important restriction |
|---|---|---|
| **All saved cameras** | Name, lens information, field of view, focal length, world position, direction, up vector, look-at, pivot, distance, spherical angles, unsaved status. | `isCameraUnsaved()` must be false; otherwise no switching starts. |
| **All saved environments** | All 14 documented `lux.Env` getters: name, lighting environment, backplate, brightness, rotation, height, size, background color and ground settings. | Temporarily selects each environment; attempts restoration. |
| **All saved image styles** | Kind, bloom, chromatic aberration, denoise, vignette and Photographic-only color/curve. | Color/curve are not called for Basic styles. |

**This is separate from “Exhaustive output.”** The latter removes most output/traversal caps but does not authorize camera, environment, or image-style switching. Neither option unlocks the two blocked native animation-object getters.

**Native scene metadata files:** Use the dedicated *Export native .metadata and .xmp files (user folder)* report to save KeyShot's original current-scene metadata in two non-overwriting files. It does not automatically create one metadata file per camera or environment.

## 8. How the crash trace works

The inspector writes a separate plain-text log called **`KeyShot_Inspector_v1_2_0_Trace.txt`**. It records a timestamped checkpoint before and after selected operations. Checkpoints are written and synchronized to disk as soon as possible to help survive a native application crash.

The trace goes in the chosen output folder **if it exists**. Otherwise, it tries KeyShot's Scripts resource directory and then the current user's home directory. The script prints the trace path near the end of a successful run. Every new run **recreates/overwrites the same v1.2.0 trace filename** in that folder, so copy it before running the inspector again.

**Normal operation (illustrative abbreviated excerpt):**

```text
2026-10-23T17:00:10 | SCRIPT START
2026-10-23T17:00:10 | MAIN OPTIONS ACCEPTED
2026-10-23T17:00:12 | INDIVIDUAL DIALOG START: Animation
2026-10-23T17:00:13 | INDIVIDUAL DIALOG END: Animation
2026-10-23T17:00:13 | GET START: Animation :: getAnimationInfo() / Time / Frame
2026-10-23T17:00:13 | ANIMATION STATUS START: lux.getAnimationInfo()
2026-10-23T17:00:13 | ANIMATION STATUS END: lux.getAnimationInfo()
2026-10-23T17:00:13 | ANIMATION STATUS START: lux.getAnimationTime()
2026-10-23T17:00:13 | ANIMATION STATUS END: lux.getAnimationTime()
2026-10-23T17:00:13 | ANIMATION STATUS START: lux.getAnimationFrame()
2026-10-23T17:00:13 | ANIMATION STATUS END: lux.getAnimationFrame()
2026-10-23T17:00:13 | GET END: Animation :: getAnimationInfo() / Time / Frame
2026-10-23T17:00:13 | REPORT COMPLETE: ...
```

**Suspected crash (illustrative):**

```text
2026-10-23T17:03:02 | GET START: Animation :: getAnimationInfo() / Time / Frame
2026-10-23T17:03:02 | ANIMATION STATUS START: lux.getAnimationInfo()
```

If the log ends there, `getAnimationInfo()` was the last documented operation entered. **It is a clue, not conclusive proof of the root cause.** A crash or forced shutdown can interrupt logging for unrelated reasons. An ordinary caught Python exception usually produces `[ERROR]` text and may still reach `GET END`.

The file may also contain `LIBRARY START` / `LIBRARY END`, `ANIMATION NATIVE GETTER BLOCKED`, `NOTE scene tree traversal capped`, `CANCELLED`, and `PYTHON ERROR` entries. With all-saved-item inspection enabled, it additionally records `CAMERA`, `ENVIRONMENT`, or `IMAGE STYLE` checkpoints for `SWITCH START/END`, `VERIFY ACTIVE START/END`, `READ START/END`, **individual property** `GET START/END`, `RESTORE START/END`, and possibly `ABORT`. A missing restore-END checkpoint is especially important to review.

**What to share for troubleshooting:** copy the **last 20–40 trace lines**, the end of the partial TXT report, the category and checkboxes selected, KeyShot exact version, and whether the scene is saved and has animations/material graphs. Please redact local usernames, network paths, machine identifiers, license information and proprietary asset names first.

## 9. Reading the TXT report

Each selected category gets a section title. Within it, a reporter header is followed by plain-text results. Depending on the selected option, you may see names, dictionaries, native KeyShot object representations, shader node IDs, parameters, edges, or bounds.

Common annotations:

| Text | Meaning |
|---|---|
| `(none)` | No applicable value was returned or the collection was empty. |
| `[ERROR: ...]` / `[ERROR]` | A Python/API read error was recorded; inspect that subsection. |
| `[TRUNCATED]` | The configured output or traversal limit was reached; increase cautiously or narrow the selection. |
| `[SKIPPED SAFELY]` | A slow or advanced option is disabled until explicitly opted in. |
| `[SKIPPED - NATIVE CRASH PRECAUTION]` | `getAnimations()` or `getNodeAnimations()` was intentionally **not executed**, regardless of checkbox selection. |
| `POTENTIALLY UNUSED` | A material graph diagnostic candidate, **not** an instruction to delete a node. |
| `N/A (Basic image style)` | KeyShot only supports Color/Curve getters for Photographic image styles. |
| `REPORT END` | The script finished its selected report operations; shows counts, skip counts and recorded error markers. |

**Important:** IDs for scene objects, shader nodes and edges are typically session-specific. Preserve names and full paths alongside IDs if you plan to compare reports after reopening a scene.

The inspector writes the TXT incrementally and calls `fsync()` after each completed operation. A KeyShot process crash may still leave an unfinished section. Console output is a preview capped at about **1,800 characters per GET**, even if the saved TXT includes more.

## 10. Animation and read-only limits

- **Basic animation status** reads `getAnimationInfo()`, `getAnimationTime()` and `getAnimationFrame()` without changing the timeline. Each getter has its own checkpoint.
- **Advanced animation hierarchy and current-frame bounds** require their separate checkbox. They traverse the scene tree but **do not advance to other frames**.
- **`lux.getAnimations()` and `lux.getNodeAnimations()`** are documented by the 2026 API but **disabled in this script following reports of native KeyShot crashes**. Their checkboxes report *availability* only, not live data.
- **Saved cameras:** the standard camera getters describe only the active camera. The **ALL saved cameras** report can inspect each saved camera when the user explicitly authorizes temporary switching. It checks for unsaved camera changes and attempts restoration after each camera. The corresponding all-saved environment and image-style reports work similarly. If KeyShot terminates natively, Python's `finally` block cannot guarantee restoration.
- **Unsupported export requests:** no RGB conversion, camera quaternion computation, COLMAP export, material assignment/conversion, node deletion, geometry-node reconnecting, frame baking or render initiation.

## 11. Library and CMF operations

**CMF = Color, Material, Finish.** The CMF reporter is a **named material-library metadata lookup**; it is not the same as scene-wide `getMetaData()` or node-specific `SceneNode.getMetadata()`.

To use it, type the exact material-library name in the first dialog, check **Allow slow scans / library loading**, then select **Materials / graphs / parameters → MaterialMetadata.getFieldNames/readField (library)** in Individual Gets mode. KeyShot's API can list metadata fields, but `readField()` cannot read image-type metadata contents. If the name is missing, the inspector says so.

**Library Inventories** runs five KeyShot `getLibrary*()` functions, not a whole-hard-drive walk. KeyShot's 2026 documentation warns that first-time resource-library loading can block. **Resource Models** is a separate Python filesystem scan, limited to the resource Models directory and bounded to at most 150 scanned directories or 300 matching `.bip`/`.ksp` paths. Both require slow-scan opt-in.

## 12. Troubleshooting

| Symptom | What to do |
|---|---|
| **KeyShot closes while inspecting** | Copy the trace before rerunning; find the last `GET START` or inner `ANIMATION STATUS START` / `LIBRARY START` without a matching END. Rerun a smaller selection. |
| **Crash in main options dialog** | A new trace might not exist because initialization starts after the first dialog closes. Note which control was being used. |
| **Crash in Individual Gets picker** | Look for `INDIVIDUAL DIALOG START` without `INDIVIDUAL DIALOG END`; report category and exact KeyShot build. |
| **Library request appears to hang** | Keep slow scans disabled by default; test one of the resource operations separately. Initial library loading may block. |
| **Many `[TRUNCATED]` notes** | Raise per-GET output limit conservatively or run individual getters on a smaller category; also review the scene cap. |
| **Unexpected missing nodes/materials** | Default caps are 700 scene nodes, 40 materials and 120 graph nodes per material. Run focused reports first; consider Exhaustive only when necessary. |
| **All saved cameras/environments/styles are skipped** | Enable the main-dialog **Inspect ALL ... via switching/restoring** checkbox; selecting the reporter alone is not enough. Save a scene copy first. |
| **All-camera scan declines to run** | The camera has unsaved changes or `isCameraUnsaved()` could not be read. Save the camera and try again on a saved scene copy. |
| **Restoration error / active selection changed** | Stop other diagnostic runs, check the last `RESTORE` / `ABORT` trace entries, and verify the active camera, environment, or image style manually. |
| **Output unexpectedly cut off** | Standard per-GET and node limits may truncate reports. Exhaustive mode lifts most caps but not Resource Models filesystem-scan bounds. |
| **Native metadata export missing** | Select the dedicated export operation and an existing writable TXT output folder. It writes *two additional files* even if the main report destination is Console only. |
| **Basic image style `Color/Curve` unavailable** | This is expected and protected; those getters apply only to Photographic styles. |
| **Animation native getters show skipped** | Intentional crash precaution, not proof the API methods are absent. |
| **No TXT was saved** | Confirm output mode is not Console only, folder exists, and Python has write permission; inspect `PYTHON ERROR` in the trace. |
| **No report data for CMF material** | Exact library name, CMF report checkbox, and slow-library opt-in are all required. |

## 13. Sharing reports safely

Text reports can include **scene filenames, folder paths, node names, proprietary material names, external assets, metadata, computer hardware, process paths and license details**. **Do not upload an unreviewed full report to a public forum**. Remove anything sensitive from the TXT and trace first.

This is an **unofficial community utility**. It uses the KeyShot 2026 API as documented by the supplied built-in `help(lux)` dump; results can vary by KeyShot build, scene contents, edition and licensing. Offline checks do not replace KeyShot runtime testing.
