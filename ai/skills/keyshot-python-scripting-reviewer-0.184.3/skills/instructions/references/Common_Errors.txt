### Define input fields for the dialog

When using `lux.getInputDialog()` to create custom input dialogs in KeyShot, ensure that all fields, especially those of type `lux.DIALOG_TEXT`, have non-empty default values. This requirement prevents runtime errors related to uninitialized or empty fields in the dialog.

### Create the dialog

Common Errors:

**Empty Item Tuple Exception:**

**Error Message:** Exception: Items of item tuple must be specified!

**Cause:** This error occurs when a tuple expected by a function like `lux.getInputDialog()` is incomplete or improperly formatted, particularly for selection items (`lux.DIALOG_ITEM`).

**Solution:** Ensure that all tuples defining dialog items are complete and correctly formatted. For selection items (`lux.DIALOG_ITEM`), include all required elements: the label, item type, description, default selection, and a list of options.

---

**Type Mismatch Error:**

**Error Message:** TypeError: argument 1 must be str, not list

**Cause:** This error is typically raised when a function expects a string argument, but a list (or another non-string type) is provided instead.

**Solution:** Carefully review function calls to ensure that all arguments are of the expected type. For functions expecting a string, do not pass lists or other composite types without first converting or extracting the appropriate string value.

---

**Implementation Tips:**

**Debugging:** Use print statements or logging to debug argument types and values passed into functions. This can help identify where type mismatches occur.

**Type Checking:** Implement explicit type checks or use Python's type hinting to make your code clearer and catch type-related errors early.

**Consistent Formatting:** When dealing with functions that require tuples (like `lux.getInputDialog()`), double-check the consistency and completeness of your tuples to prevent formatting-related exceptions.

**Example:** Here is an example illustrating how to correctly define a field in `lux.getInputDialog()` with a non-empty default value:

```python
# Define input fields for the dialog
values = [
    ("name", lux.DIALOG_TEXT, "Model Name:", "DefaultModelName"),  # Non-empty default value
    # Other fields as needed
]

# Create the dialog
opts = lux.getInputDialog(title="Model Import Settings",
                          desc="Configure settings for importing models.",
                          values=values)
```

### Correctly getting the active camera's information

The error "string indices must be integers, not 'str'" indicates that somewhere in your script, you are trying to use a string as an index for a list, which is not allowed in Python.

### Understanding the `'str'` Error

**Initial Error:**
- The error message "TypeError: string indices must be integers, not 'str'" occurs when you try to use a string as an index for a list. This typically happens when you expect a dictionary (which allows string keys) but get a list or a string.

**Error Context:**
- The error arose in the context of trying to access studio attributes using string keys, which implied that the data structure wasn't what we expected.

---

### Steps to Fix the Error

1. **Inspecting the Data Structure:**
   - We added debug prints to inspect the data returned by the `lux.getStudios()` function. This helped us understand that `lux.getStudios()` was returning a list of studio names (strings) rather than a list of dictionaries or objects with `id` and `name` keys.

```python
def get_all_studios():
    studios = lux.getStudios()
    print("Studios:", studios)  # Debug print to check the structure
    return studios
```

2. **Identifying the Correct Method:**
   - Since `lux.getStudioSettings()` did not exist, we inspected the available methods and attributes of the `lux.Studio` object using `dir()`:

```python
def inspect_studio_methods(studio_name):
    studio = lux.getStudio(studio_name)  # Retrieve the studio object
    methods = [method for method in dir(studio) if callable(getattr(studio, method))]
    attributes = [attr for attr in dir(studio) if not callable(getattr(studio, attr)) and not attr.startswith("__")]
    return methods, attributes
```

3. **Using Correct Methods:**
   - Based on the inspection, we identified the appropriate methods available on the `lux.Studio` object: `getCamera()`, `getEnvironment()`, `getImageStyle()`, `getModelSets()`, `getMultiMaterials()`, `isMultiMaterialsEnabled()`, and `getName()`.

4. **Updating the Script:**
   - We updated the script to use these methods to retrieve the settings for each studio:

```python
import lux

def get_all_studios():
    studios = lux.getStudios()  # Retrieve all studios
    return studios

def get_studio_settings(studio_name):
    studio = lux.getStudio(studio_name)  # Retrieve the studio object
    # Extract settings from the studio object using available methods
    studio_settings = {
        'name': studio.getName(),
        'camera': studio.getCamera(),
        'environment': studio.getEnvironment(),
        'image_style': studio.getImageStyle(),
        'model_sets': studio.getModelSets(),
        'multi_materials': studio.getMultiMaterials(),
        'is_multi_materials_enabled': studio.isMultiMaterialsEnabled()
    }
    return studio_settings

def main():
    studios = get_all_studios()
    all_studio_settings = {}
    
    for studio in studios:
        settings = get_studio_settings(studio)
        all_studio_settings[studio] = settings
    
    return all_studio_settings

if __name__ == "__main__":
    studio_settings = main()
    for studio, settings in studio_settings.items():
        print(f"Studio: {studio}")
        for setting, value in settings.items():
            print(f"  {setting}: {value}")
```

### Summary

**Error Cause:** The `'str'` error was caused by trying to use a string key to index into a string or list, which isn't allowed.

**Solution:**
1. **Inspect the Data:** We used debug prints to understand the structure of the data returned by `lux.getStudios()`.
2. **Identify Methods:** We inspected the `lux.Studio` object to identify available methods.
3. **Update Script:** We used the correct methods to extract the required settings from the `lux.Studio` object.

By following these steps, we correctly retrieved and displayed the settings for each studio without encountering the `'str'` error.

### Common Errors: Handling `opts` from `lux.getInputDialog`

**Issue:**
When using `lux.getInputDialog` to create a dropdown selection dialog in KeyShot, the returned `opts` for the selected item may be a list, not just the string name of the selected preset. This can lead to errors if the script attempts to use the entire list instead of extracting the needed string name.

**Explanation:**
The `opts` dictionary returned by `lux.getInputDialog` contains the user’s selections. For a dropdown (`lux.DIALOG_ITEM`), the selected item is often returned as a list. This list typically includes:
- The index of the selected item.
- The string name of the selected item.

For example:
```python
opts = {"preset": [1, "Basic"]}
```
In this case, the `preset` key maps to a list where `1` is the index of the selected item in the dropdown, and `"Basic"` is the string name of the selected lighting preset.

**Solution:**
To correctly handle the returned `opts`, extract the string name from the list before using it. Here’s how:

1. **Check if `opts` contains the expected key**:
    ```python
    if "preset" in opts:
    ```

2. **Ensure the value is a list with the expected structure**:
    ```python
    selected_preset_info = opts["preset"]
    if isinstance(selected_preset_info, list) and len(selected_preset_info) == 2:
    ```

3. **Extract the string name**:
    ```python
    selected_preset = selected_preset_info[1]
    ```

4. **Use the extracted string name**:
    ```python
    success = load_lighting_preset(selected_preset)
    ```

By following these steps, you ensure that only the string name of the preset is used, avoiding errors caused by passing a list to functions expecting a string.

### KeyShot Scripting: Handling Material Graphs

When working with material graphs in KeyShot via Python scripting, it's crucial to utilize the correct functions provided by the `lux` module for accessing and manipulating materials. The `MaterialGraph` class encapsulates a graph of material nodes constituting a material in the scene, enabling manipulation of material parameters, addition/removal of material nodes, and their association with input and output edges.

**Accessing Material Graphs and Handling Errors**

**Function to Use:**
To get a material graph, use `lux.getMaterialGraph(name)`, where name is the name of the material.

**Common Errors:**

**AttributeError:** module 'lux' has no attribute 'getMaterial'. Did you mean: 'MultiMaterial'?
**AttributeError:** module 'lux' has no attribute 'getMaterials'. Did you mean: 'getCameras'?

**Solutions:**
These errors typically occur when attempting to access materials or their properties using incorrect or non-existent `lux` module functions.

**Correct Usage:**
- Use `lux.getMaterialGraph(name)` to access the material graph of a specific material by its name.
- To obtain information about materials used in the scene, or to manipulate materials directly, consider using the following functions correctly:
  - `lux.getSceneMaterials()`: Retrieves currently used materials in the scene.
  - `lux.getName()`: Retrieves the name of a node, which can be useful when working with materials and model sets.
  - `lux.getMaterialNodes()`: Retrieves a list of material root nodes within a material graph. For multi-materials, it returns individual sub-material roots; for regular materials, it returns a list with a single item equivalent to getRoot().

**Correcting Misused Functions:**
- **Incorrect Use:** Attempting to use `lux.getMaterial()` or `lux.getMaterials()` directly, which are not valid functions and can lead to `AttributeError`.
- **Correction:** Utilize the correct functions for your intended operations, such as `lux.getSceneMaterials()` for retrieving materials or `lux.getMaterialGraph(name)` for accessing a material's graph.

**Implementation Tips:**
- **Review KeyShot Python API Documentation:** Always refer to the most current KeyShot Python API documentation to understand available functions and their proper usage.
- **Debugging:** Use print statements to debug the names and types of variables, especially when passing them as arguments to functions, to ensure they match the expected values.

By adhering to these guidelines and utilizing the correct functions for accessing and manipulating material graphs in KeyShot, you can avoid common errors and enhance your scripting workflow.

### Example Script: Importing a Model and Rendering an Image

Here's a sample script that imports a model and renders an image, demonstrating some of the best practices mentioned above:

```python
import lux
import luxmath
import os

def import_model(file_path):
    """Import a model into KeyShot."""
    if not os.path.exists(file_path):
        raise FileNotFoundError(f"File {file_path} not found")
    
    opts = lux.getImportOptions()
    opts["snap_to_ground"] = False
    opts["adjust_environment"] = False
    opts["adjust_camera_look_at"] = False
    
    success = lux.importFile(file_path, opts=opts)
    if not success:
        raise RuntimeError("Failed to import model")
    
    print(f"Successfully imported {file_path}")

def render_image(output_path, width=1200, height=1000):
    """Render an image from the current scene."""
    opts = lux.getRenderOptions()
    opts.setMaxTimeRendering(10)
    
    success = lux.renderImage(output_path, width=width, height=height, opts=

opts)
    if not success:
        raise RuntimeError("Failed to render image")
    
    print(f"Image rendered and saved to {output_path}")

def main():
    """Main function to import a model and render an image."""
    try:
        model_path = "/path/to/your/model.obj"
        output_image_path = "/path/to/save/image.png"
        
        import_model(model_path)
        render_image(output_image_path)
        
    except Exception as e:
        print(f"An error occurred: {e}")

if __name__ == "__main__":
    main()
```
