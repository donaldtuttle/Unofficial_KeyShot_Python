KeyShot Python Basics: 
Since KeyShot scripting is based on Python, getting comfortable with Python's syntax, data types, control structures (like loops and conditionals), and basic data structures (like lists and dictionaries) will provide a strong foundation.

KeyShot Scripting Environment: 
Familiarize yourself with the KeyShot Scripting Console and how to execute scripts within KeyShot. It’s a great place to test small snippets of code and see immediate results in the KeyShot environment.

Exploring KeyShot Scripting Documentation:
Documentation: KeyShot provides documentation on its Python API, accessible directly through the Help menu in KeyShot. This documentation is invaluable for understanding what functions and classes are available for scripting.

Practical Exercises:

Start Small: 
Begin with simple scripts, like changing the color of a material or automating camera movements. Gradually increase complexity as you become more comfortable.
Scripting Challenges: Set small, achievable goals, such as automating a part of your workflow that you find repetitive. This could be as simple as exporting renderings with different camera angles or applying materials to multiple models programmatically.

Debugging and Problem Solving:
Debugging: Learn the basics of debugging Python scripts. KeyShot's Script Console will show errors and print statements, which can help you understand what your script is doing and identify any issues.
Online Communities: Don’t hesitate to seek help from online forums or communities. The KeyShot forum itself can be a great resource, as well as broader Python programming communities.

Best Practices:
Version Control: As you become more comfortable with scripting, consider using a version control system like Git. This allows you to track changes to your scripts over time, making it easier to experiment without losing work.
Read and Refactor: Read other people's code whenever possible. This can provide new insights and techniques that you can incorporate into your own scripts. Also, regularly revisit and refactor your code to improve its efficiency and readability.

Continuous Learning:
Keep Exploring: The world of scripting and automation is vast. As you grow more confident in your skills, explore more advanced topics like creating user interfaces within KeyShot, integrating with external APIs, or even automating the entire pipeline from model import to final rendering.


lux Library Classes:
The lux library within KeyShot's Python environment includes a variety of classes designed to interact with and manipulate aspects of KeyShot scenes, from rendering settings and materials to scene structure and camera settings. Here's a detailed list of the classes available in the lux library:

Quick Reference:

###KeyShot Python API Classes and Their General Functionalities###-
1. ColorParameter: Manages color-related parameters in materials or environments.
2. Colorway: Handles colorway settings for multi-materials or studios.
3. Env: Configures environment settings like background, lighting, etc.
4. ImageStyle: Controls image style settings for render outputs.
5. MaterialGraph: Represents and manipulates the material graph structure.
6. MaterialMetadata: Manages metadata associated with materials.
7. MultiMaterial: Manages and configures multi-materials.
8. RenderOptions: Sets options for rendering, such as resolution and quality.
9. SceneNode: Represents nodes in the scene tree for manipulation.
10. ShaderEdge: Handles connections between shader nodes in material graphs.
11. ShaderNode: Represents individual shader nodes in material graphs.
12. ShaderParameter: Manages parameters of shader nodes.
13. Studio: Configures studio settings, including camera, environment, and model sets.
14. ThumbnailRenderOptions: Sets rendering options for thumbnails.
15. Animation: Controls animation-related settings and operations.
16. BloomParameter: Manages bloom effect parameters in image styles.
17. Curve: Represents and manipulates curve data.
18. CurveControlPoint: Manages control points for curves.
19. CurveParameter: Handles curve parameters in shader nodes.
20. DenoiseParameter: Configures denoise settings in render options.
21. Display: Controls display settings within KeyShot.
22. FlakeParameter: Manages flake effect parameters in materials.
23. GeometryNode: Represents geometry nodes in the scene.
24. GeometryShaders: Manages shaders applied to geometries.
25. Image: Handles image data and operations.
26. ImageEffects: Configures post-processing effects on images.
27. ImageLayers: Manages layers in composite images.
28. Label: Controls label properties on materials.
29. Light: Manages light sources in the scene.
30. LightMaterial: Handles materials specifically for lights.
31. Material: Represents and manipulates materials.
32. NormalMapParameter: Manages normal map parameters in materials.
33. NumberParameter: Handles numeric parameters in shader nodes.
34. OrthographicCamera: Configures orthographic camera settings.
35. PanoramicCamera: Manages panoramic camera settings.
36. PerspectiveCamera: Controls perspective camera properties.
37. ProceduralTexture: Handles procedural textures in materials.
38. RenderLayers: Manages render layers in the scene.
39. ScatteringMedium: Configures settings for volume scattering.
40. SphericalCamera: Manages spherical camera settings.
41. Texture: Represents and manipulates texture data.
42. TextureParameter: Manages texture parameters in materials.
43. ToonMaterial: Handles toon shader materials.
44. VideoMap: Manages video textures.
45. Volume: Represents volumetric materials or effects.

Differences in Classes and Functions
In headless mode, KeyShot scripting still provides access to essential classes and functions for scene manipulation, such as those related to materials, cameras, rendering, and scene nodes. However, there are specific considerations and functionalities unique to headless mode:

GUI-Dependent Features: Functions and classes that require user interaction through the GUI, such as custom input dialogs (lux.getInputDialog()), are not available or functional in headless mode. Scripts designed for headless operation should avoid relying on any form of GUI feedback or input.

Automation and Batch Processing: Headless mode emphasizes automation. Functions for importing files, setting render options, triggering renders, and exporting results are fully supported and often used in automated workflows. This includes batch rendering, where multiple scenes or variations of a scene can be rendered sequentially without user intervention.

External File Handling: Headless mode might offer more explicit control over handling external files, such as specifying paths for importing and exporting data. This is crucial for automated workflows and integration with other software tools in a production pipeline.

Command-Line Arguments: 
While not a direct part of the lux library, headless operation often leverages command-line arguments for specifying script files to run, providing parameters to scripts, and controlling KeyShot's startup behavior. This allows for dynamic script execution based on external inputs.

Performance and Resource Management: 
Headless mode may provide functions or options focused on optimizing performance and resource usage, given that it's often used on high-performance computing resources or for background processing tasks. This can include controls over memory usage, CPU threading, and GPU usage for rendering.

Consistent Core Functionality:
Despite these differences, the core functionality provided by lux and luxmath for scene construction, material application, camera control, and rendering settings is consistent between GUI and headless modes. Scripts can generally be developed in the GUI version of KeyShot and then executed in headless mode with minor adjustments, primarily related to user interaction and file path handling.

Guidelines for Making Scripts Headless Compliant
Avoid GUI Functions: Do not use functions that require GUI interaction, such as lux.getInputDialog() for custom input dialogs or any other function that prompts the user for input through the KeyShot interface.

Use Command-Line Arguments: 
For scripts that require input parameters, consider using command-line arguments to pass values into the script at runtime. This approach allows for dynamic script execution based on external inputs without needing GUI interaction.

Automate Render Settings and Execution: 
Utilize KeyShot's scripting capabilities to set all necessary render options programmatically. This includes setting camera parameters, environment settings, output resolutions, and render modes. Make sure the script triggers rendering and saves the output automatically.

Error Handling: 
Implement comprehensive error handling within the script to manage any issues that arise during execution. Since there's no GUI to display errors interactively, consider logging errors to a file or the console output for debugging purposes.

File Paths and External Resources: 
Handle file paths and external resources carefully, ensuring that paths are defined relative to the script location or passed as arguments, considering that the script may run in different environments or paths than when developed.

Output and Feedback: 
Since headless mode lacks GUI feedback, design your script to provide appropriate console output or log files to inform users of progress, completion status, and any errors or warnings.

Testing in Both Environments: 
Test your script extensively in both GUI and headless modes to ensure it behaves as expected. This helps identify any GUI-dependent operations or other issues that might only manifest in one mode.

Scene Tree:

In KeyShot, the scene tree is a hierarchical representation of all the elements within a KeyShot scene. This structure mirrors the concept of a scene graph commonly used in 3D graphics and rendering software, organizing objects, materials, cameras, lights, and other entities in a way that reflects their relationships and dependencies.

Components of the Scene Tree:
The KeyShot scene tree comprises various nodes, each representing a different aspect of the scene:

Root Node: 
The top-level node under which all other scene elements are nested. It represents the entire scene.
Geometry Nodes (Model and Part Nodes): These nodes represent 3D models and their components. A single model can be composed of multiple parts, each potentially having its own material and transformation settings.
Material Nodes: Attached to geometry nodes, material nodes define the appearance of models or parts, including color, texture, reflectivity, and other visual properties.

Camera Nodes: 
Define different viewpoints from which the scene can be rendered. Each camera node stores settings like position, orientation, focal length, and depth of field.

Light Nodes: 
Represent light sources within the scene. KeyShot supports various types of lights, including area lights, point lights, and environment lights, each with its own set of parameters.
Environment Nodes: 
These nodes are used for global illumination and background settings. They can define HDRIs (High Dynamic Range Images) used for lighting and reflections.

Animation Nodes:
If the scene includes animations, each animation is represented as a node in the scene tree, detailing the animated properties and their keyframes.

Understanding the Hierarchical Structure:
The hierarchical nature of the scene tree allows for complex relationships between objects:

Parent-Child Relationships: 
Objects can be parented to other objects, meaning the child's transformation (position, rotation, scale) is relative to its parent. This is useful for creating complex assemblies where multiple parts move together.

Grouping: 
Similar objects can be grouped under a common parent node, simplifying the organization and enabling collective transformations or property adjustments.

Instancing: 
The scene tree structure allows for instancing, where the same object or geometry node is referenced multiple times within the scene without duplicating the actual geometry data. This saves memory and makes scene management more efficient.

Manipulating the Scene Tree via Scripting:
KeyShot's Python API allows scripts to interact with the scene tree, enabling automated tasks like:

Adding or Removing Nodes: 
Scripts can create new geometry, material, camera, or light nodes and insert them into the scene tree or remove existing nodes.

Modifying Node Properties: 
Scripts can change the properties of nodes, such as transforming geometry, altering material parameters, or adjusting camera settings.



Environment Nodes:

HDRI Environment, Color Environment, etc.:
Properties: Brightness, Rotation, Background Color, etc.
Accessing Node Properties Programmatically
In a scripting context, you can access and modify these properties through KeyShot's Python API. For instance, to change the color of a diffuse material, you would access the material node associated with an object and set its color property accordingly.
Navigating the Tree: 
Scripts can traverse the scene tree, accessing parent or child nodes, to gather information or make systematic changes to the scene.

 Description of `getSceneTree()`

The `getSceneTree()` function is a part of KeyShot's Python API and is crucial for accessing and manipulating the scene graph. This function is used to retrieve the root node of the current scene in KeyShot. Once you have this root node, you can navigate through the entire hierarchy of the scene, including all objects, materials, cameras, lights, etc.

 Key Aspects of `getSceneTree()`

- **Functionality**: Retrieves the root node of the scene graph in KeyShot.
- **Return Type**: The function returns a `SceneNode` object, which represents the top-level node of the scene.
- **Usage**: Essential for scripts that need to traverse or modify the scene hierarchy.
- **No Arguments**: `getSceneTree()` does not require any arguments.

 Outline for Using `getSceneTree()`

1. **Import KeyShot lux Module**:
```python
import lux
```

2. **Retrieve the Root Node**:
```python
root_node = lux.getSceneTree()
```

3. **Traverse the Scene Graph**:
- You can now use various methods of the `SceneNode` class to traverse and manipulate the scene.
- For example, to get child nodes: `children = root_node.getChildren()`

4. **Accessing Specific Elements**:
- Use traversal methods to access specific elements like cameras, materials, or geometries within the scene.
- Perform operations like changing materials, moving objects, or adjusting camera settings.

5. **Iterative Traversal**:
- Often, you'll use a recursive function to traverse the scene tree starting from the root node to find specific nodes or perform operations on multiple nodes.

 Example Use Case

Here's a simple example demonstrating how to use `getSceneTree()` to print the names of all top-level objects in the scene:

```python
import lux

def print_scene_object_names():
root_node = lux.getSceneTree()
for child_node in root_node.getChildren():
print(child_node.getName())

print_scene_object_names()
```

In this example, `getSceneTree()` is used to start at the root of the scene graph, and then the script iterates over its direct children, printing out their names.

Remembering to use `getSceneTree()` is crucial for any script where you need to interact with the scene's hierarchy, making it a fundamental function in KeyShot Python scripting.



Material Graph:

Material Nodes:
In KeyShot, a material node essentially functions as a shader by defining how surfaces interact with light. Each material node encapsulates the properties and behaviors necessary to simulate various physical materials, such as metals, plastics, glass, and more, effectively acting as a shader in the traditional 3D graphics sense.

Understanding Shaders and Material Nodes in KeyShot:
In 3D graphics, a shader is a type of computer program used to determine the appearance of surfaces when rendered, including colors, brightness, and texture details. KeyShot abstracts the complexity of shader programming into a more user-friendly interface through its Material Graph, where:

Material Nodes represent different types of materials (or shaders) that can be applied to objects in a scene. Each type of material node has its unique set of properties that mimic physical material characteristics, such as roughness, refractive index, or metallic properties.

Texture Nodes and Utility Nodes within the Material Graph can be used in conjunction with material nodes to further customize the material's appearance. For example, texture nodes can provide bitmap textures or procedural patterns, while utility nodes can perform operations like blending, color adjustment, or mathematical computations.

Example of Shader Material Nodes:
Some examples of shader material nodes in KeyShot include:

Diffuse Material: Simulates non-reflective surfaces, primarily defined by its color.
Metal Material: Represents metallic surfaces, with properties for controlling metalness and roughness.
Glass Material (Transparent Material): Used for creating transparent materials with control over refraction and transparency.
Plastic Material: Offers a way to simulate various plastic finishes with adjustable glossiness and translucency.
Paint Material: Designed to simulate painted surfaces, including options for clear coat layers.
Each of these material nodes has parameters that allow you to fine-tune the appearance of the material, mirroring the role of shaders in a traditional rendering pipeline but in a more accessible manner.

Accessing and Modifying the Material Graph through Scripting:
You can script the Material Graph in KeyShot using KeyShot's Python scripting API. Scripting the Material Graph allows for automated creation, modification, and application of complex materials programmatically, enabling tasks such as batch processing of materials, procedural material generation, and dynamic adjustments based on external data.

The scripting API provides access to the Material Graph components, including nodes, connections, and parameters. Here are some fundamental concepts for scripting the Material Graph:

Accessing the Material Graph: 
You start by accessing the material graph of a specific material. Each material in KeyShot that has a Material Graph can be accessed through scripting.

Creating and Connecting Nodes: 
The API allows for creating various types of nodes (such as material, texture, and utility nodes) and establishing connections between them to define the flow of information within the graph.

Editing Node Properties: 
Once nodes are created and connected, you can script changes to their properties, like changing texture settings, modifying colors, or adjusting material parameters.

Applying Materials: 
After creating or modifying a material in the Material Graph through scripting, you can apply it to parts of your scene programmatically.

Root Node:
In KeyShot's Material Graph, the concept of a "root node" refers to the primary material node that defines the base properties of the material being constructed or edited within the graph. This root node isn't directly analogous to surface/object/model/assembly/part in the scene hierarchy; instead, it serves as the foundational element within the material's node graph from which additional properties and effects are derived through connections with other nodes (like textures, utilities, color adjustments, etc.).

Understanding the Root Node in a Material Graph Context:
Material Graph Root Node: The starting point or the base material type for your material design within the Material Graph. It defines the essential characteristics of the material, such as whether it's a metal, plastic, paint, glass, etc. This node is where you begin building your material by adding and connecting other nodes to enhance or modify its properties.

Name of the Root Node: The name of the root node corresponds to the type of material it represents. For example, if you're creating a metal material, the root node might be named "Metal Material" or simply "Metal." In KeyShot, the specific name would depend on the material type selected when you start building or editing the material in the Material Graph.

Role of the Root Node:
The root node's role is crucial because:

It determines the fundamental nature of the material (reflective, transparent, diffuse, etc.).

It acts as the anchor point for additional nodes that introduce textures, patterns, and effects (e.g., roughness maps, bump maps, color adjustments).

It is where the material's primary properties are set, which other nodes can then augment or override.
Application to Surfaces/Objects/Models

Once a material is created in the Material Graph, it can be applied to surfaces, objects, models, parts, or assemblies within KeyShot's scene hierarchy. Here, the terms "surface," "object," "model," "assembly," and "part" refer to different elements in the scene to which materials can be assigned:

Surface: 
A specific area of a model that can have a unique material.
Part: A component of a model that may consist of one or more surfaces.
Object/Model: Typically, an imported geometry that can consist of multiple parts.
Assembly: A group of objects or models that form a larger structure within the scene.
The relationship between the Material Graph and these scene elements is that the materials designed in the Material Graph are applied to these elements to define their appearance. The "root node" within the context of the Material Graph is about the material's properties and is distinct from the scene hierarchy where objects, models, parts, and assemblies reside.

Scripting Material Graph:
Material Graph Manipulation (GUI and Headless)
Manipulating the Material Graph via Scripting is an advanced feature that has been added in KeyShot 11.

The following will go through the basic functions to manipulate the Material Graph. To see a full list of functions available, type help(lux) in the Scripting Console or visit the online documentation, for GUI or Headless scripting.

Access material graph
You can access the material graph like this:

graph = lux.getMaterialGraph("name")
The graph is an instance is of the type lux.MaterialGraph which you can interact with.

Access root node
You can access the root node with the following:

rootNode = graph.getRoot()
The rootNode is an instance is of the type lux.ShaderNode which you can interact with.

Get input edges of a node
However a node instance was obtained, you can get the edges from a Material Graph by typing:

edges = node.getInputEdges()
Each edge instance is of the type lux.ShaderEdge that you can be interact with.

A specific edge can be obtained via:

edge = node.getInputEdge("parameter name")
This will yield lux.ShaderEdge or an error if the name is unknown.

Get output edges of a node
However a node instance was obtained, you can get the edges from a Material Graph by typing:

edges = node.getOutputEdges()
Each edge instance is of the type lux.ShaderEdge that you can be interact with.

Get parameters of a node
However a node instance was obtained, you can get the parameters from a Material Graph by typing:

parameters = node.getParameters()
Each parameter instance is of the type lux.ShaderParameter that you can be interact with.

A specific parameter can be obtained via:

parameter = node.getParameter("parameter name")
This will yield lux.ShaderParameter or error if unknown name.

Change parameter value
A parameter, parameter, obtained via lux.SceneNode.getParameter() or lux.SceneNode.getParameters(), can have its value modified via lux.ShaderParameter.setValue().

If, for example, the parameter’s type was a boolean (true or false), you could change the value via:

parameter.setValue(True)
Is the value supported as input but entered incorrectly it will be shown in a python exception.

If, for example, the parameter was an RGB color and you applied the boolean value, it would yield the error:

Color parameter only accepts values of type tuple or list of size 3 containing floats or ints within range [0.0,1.0], or a color name!
The following would therefore be the correct input for a color parameter:

parameter.setValue((0.5, 0, 0))  # Red, (0x7F, 0x00, 0x00)
parameter.setValue("Amber")      # Color known by the color library in KeyShot
You can obtain a Python value via lux.ShaderParameter.getValue() to get an understanding of what’s supported or you can print a representation of the instance (str() or repr()).

Remove a node
You can remove a node, either via the instance:

graph.removeNode(node)
Or its ID:

graph.removeNode(node.getID())
Create a new node
You can for example create a metal node like this:

metalNode = graph.newNode(lux.SHADER_TYPE_METAL)
Remove an edge
You can remove an edge, either via the instance:

graph.removeEdge(edge)
Or its ID:

graph.removeEdge(edge.getID())
Create an edge between two nodes
You can for example create an edge between node1 and node2 on the surface parameter:

edge = graph.newEdge(source=node1, target=node2, param="surface")
